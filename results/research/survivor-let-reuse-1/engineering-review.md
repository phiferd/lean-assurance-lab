# Prelaunch engineering review

No research process had launched during these corrections. The first delegated
runner draft omitted active-time enforcement, expected a pre-existing mutant
binary, passed an export stream where Nanoda expects a config, compared the
build output against itself, and misclassified candidate acceptance. The lead
replaced the uncommitted draft with explicit science/authority bindings, paired
clocks, counted immutable build products, config adapters and strict outcomes.
The discarded draft was never frozen or used as evidence. Worker test output
was returned in conversation; raw log files were not captured and are not
reconstructed here.

The first local dependency binder required every package in Cargo.lock for a
vendor directory. The host cache lacked the target-specific wasi package, which
is reached through dev dependencies. That preflight does not establish that a
macOS release build needs it. Its manifest is preserved in diagnostics; the
same-item repair binds an isolated copy of available registry source/archive
payloads and index, with offline resolution and unchanged source/lock. Only a
counted offline build may establish whether the host closure is sufficient.

The expected Nanoda rejection is an assert_def_eq assertion panic inside
infer_let. The proposal explicitly targets that path. The operational definition
of TYPECHECK_REFUSAL therefore requires this specific baseline-candidate path;
generic fatal/panic/parser/timeout outcomes remain separate. RUST_BACKTRACE=full
is a fixed observation setting and changes neither export bytes nor checker
configuration. An unavailable signature is an audit/attribution gap to diagnose,
not a scientific mismatch or permission to alter the pair.
