# Resource envelope pilot 1: candidate protocol

Status: preparation draft; not a freeze, construction approval, or launch approval. The scientific and execution manifests will bind exact committed bytes after independent review. Only synthetic, disjoint fixtures may exercise tooling before then.

## Question and finite selection

Measure elapsed wall time and memory observations for two closed, type-valid Lean expression families checked at six fixed binder counts by two retained implementations. The 24 ordered cells are observer-major: official Lean 4.33.0 then Nanoda `6ae1f0c`, each Pi then let, each at 16, 32, 64, 128, 256, 512. The result applies to these cells, input encodings, host, and controls only. A reported limit is a measured finite boundary, not an asymptotic or universal performance claim.

For each family and size `n`, one source file contains exactly one safe definition in namespace `ResourceEnvelopePilot1`. Case IDs are `rep1-pi-{n:03d}` and `rep1-let-{n:03d}`. Declaration names are `ResourceEnvelopePilot1.pi{n:03d}` and `.let{n:03d}`. Case ordinal is zero-based, Pi slots 0–5 then let slots 6–11. The 24 observation cell IDs prepend `official` or `nanoda` to the case ID.

### Exact source construction rule

The source file is UTF-8 ASCII with LF line endings and one final LF. Its first line is `-- Generated by resource-envelope-pilot-1; exact scientific input.`; the second line is `namespace ResourceEnvelopePilot1`, followed by a blank line. The sole definition line is `def {family}{n:03d} : Sort 1 := {value}`. A blank line and `end ResourceEnvelopePilot1` plus final LF follow. No imports, attributes, universe variables, axioms, other declarations, commands or comments occur.

Pi value: start from terminal `Sort 0`; for `i=n-1` down to 0 replace the current body with `(forall (x{i:03d} : Sort 0), {body})`. Thus every binder domain is `Sort 0`, and the final codomain is `Sort 0`. Let value: start from terminal `x{n-1:03d}`; for `i=n-1` down to 0 replace the current body with `(let x{i:03d} : Sort 1 := {rhs}; {body})`, where `rhs` is `Sort 0` for `i=0` and `x{i-1:03d}` otherwise. There is exactly one lexical reference to the immediately previous let binder in each later value and one to the final binder in the terminal body. Both renderers are pure and deterministic; no RNG, retries or outcome-based selection exists.

Every exported Pi must have `binderInfo:"default"`; every exported let must have `nondep:false`. Let annotations and values are outside that let binder's scope, while its body is inside. The auditor checks these fields, exact de Bruijn references and all binder names rather than accepting a merely alpha-equivalent export.

### Independent typing argument and audit

`Sort 0` has type `Sort 1`. In the Pi tower each domain and final codomain therefore has type `Sort 1`, and the Pi universe rule yields type `Sort 1` at every level (`imax 1 1 = 1`). Each let annotation is `Sort 1`; the first value `Sort 0` has that type, every later value refers to the immediately preceding variable of that type, and the final body refers to the last. The complete let chain has type `Sort 1` and zeta-reduces to `Sort 0`. Both families are closed. For `n≥1`, the value's expanded AST-node count is `2n+1` for Pi and `3n+1` for let, root-counted expression depth is `n+1`, and binder depth is `n`. These are derivations from the frozen grammar, not checker votes.

Each case must independently audit the exact source bytes and parse the export graph without importing the producer's term constructors or expectations. The audit reconstructs the exact de Bruijn expression from the formula, verifies all references and binder scopes, exact declared type/value/name, exactly one safe total definition (`safety=safe`, no partial/unsafe, axiom or opaque), no other declarations, no universe parameters and no dependency constants. It checks export metadata/version, names, levels, expression tags, binder information and let scope/`nondep` representation, rejects malformed/duplicate/extra records, and recomputes metrics. A successful observer exit or printed count is never substituted for this audit. Every exact generated case and export must pass the auditor before launch; an invalid selected input halts science rather than being replaced.

The producer writes `corpus/sources/<id>.lean`, `corpus/exports/<id>.ndjson`, `corpus/cases/<id>.json`, then a corpus index in exact case order. Paths in case/index records are relative to the item's `results/research/resource-envelope-pilot-1/` directory. For each case, the retained Lean 4.29.1 toolchain builds a fresh temporary Lake workspace containing the exact source bytes at `ResourceEnvelopePilot1.lean`, `lean-toolchain` containing `leanprover/lean4:v4.29.1\n`, and a `lakefile.toml` defining one Lean library named `ResourceEnvelopePilot1`. The build command is `lake build ResourceEnvelopePilot1`; export is `lake env <pinned lean4export binary> ResourceEnvelopePilot1 -- <exact declaration name>` with that workspace as cwd. The producer retains command, environment, stdout/stderr, exit, elapsed, supervision and output hashes for every build/export attempt. The execution manifest binds absolute toolchain identity, exact workspace file templates, argv, environment and limits before construction. No observer runs during this stage.

The first export line must be exactly the 173-byte UTF-8 line `{"meta":{"exporter":{"name":"lean4export","version":"3.1.0"},"format":{"version":"3.1.0"},"lean":{"githash":"f72c35b3f637c8c6571d353742168ab66cc22c00","version":"4.29.1"}}}\n`, byte-checked against the retained format 3.1.0 example. There may be only `in` name, `il` level and `ie` expression records after it, followed by exactly one final `def` record. No other metadata keys, records, unreachable/dead nodes, dependencies or declarations are permitted. The independent auditor reconstructs the graph and rejects missing, duplicate, dangling, extra or nonallowed records. The `def` must resolve to the exact declaration name, type and value, with exact metadata keys `name`, `levelParams`, `type`, `value`, `hints`, `safety`, `all`; `safety="safe"`, `hints={"regular":1}`, empty `levelParams`, `all` containing only its name, and no other declaration kind. Inputs contain no constant references, metadata expressions, applications, lambdas, recursors, projections, literals, or nonzero universe parameters.

Case JSON exact keys are `schema_version`, `id`, `ordinal`, `family`, `size`, `declaration`, `expected_type`, `source`, `export`, and `metrics`. `schema_version` is integer 1; `expected_type` is `Sort 1`. `source` and `export` each have exactly `path`, `bytes`, `sha256` for exact file bytes. `metrics` has exactly `serialized_bytes`, `reachable_dag_nodes`, `expanded_value_nodes`, `binder_depth`, `dependency_declarations`; serialized bytes equals export bytes; reachable DAG nodes counts distinct expression IDs reachable from the definition **value** only (excluding type, levels, names and records); expanded nodes recursively unfolds value sharing; dependency declarations must equal zero. JSON uses sorted keys, compact separators, UTF-8, no NaN/infinity/duplicate keys, and one final LF. Booleans are rejected for integer fields.

`corpus/index.json` has exactly `schema_version:1`, `item_id:"RESOURCE-ENVELOPE-PILOT-1"` and a `cases` array of twelve entries in ordinal order. Each entry has exactly `id`, `ordinal`, `family`, `size`, and `case`, with `case` an exact `path`, `bytes`, `sha256` binding to `corpus/cases/<id>.json`. The independent corpus auditor rejects missing, extra, duplicated, misordered or changed rows and extra files in the three corpus subdirectories. The index uses the same canonical JSON encoding and final LF.

## Comparable checking task and baseline

Both checkers receive the **same immutable export bytes** for a given case. The official adapter runs the retained `kernel` without `--parse-only` and requires exit 0, exact `Accepted 1 declarations.\n` on stdout and empty stderr. Nanoda runs the retained `nanoda_bin` with a newly bound config: stdin export bytes, one checker thread, `print_success_message=true`, `unpermitted_axiom_hard_error=true`, `unsafe_permit_all_axioms=false`, and no extensions; it requires exit 0, exact `Checked 1 declarations with no errors\n` and empty stderr. The independent audit proves the export contains one safe definition actually eligible for both checking paths. This establishes equivalent *checking task and acceptance signal* for the exact exported declaration; it does not equate internal algorithms or treat agreement as semantic authority.

The zero-declaration baseline uses one frozen metadata-only NDJSON line with the same producer/version fields as the scientific exports. Each checker runs its same full invocation/config on that exact empty input, with expected `Accepted 0 declarations.\n` or `Checked 0 declarations with no errors\n`. Run a fixed three baseline repetitions per profile before that profile's first scientific cell and three after its last, in ordinal order. These include process startup, parsing and empty checking; they do not isolate or subtract import cost. Preserve individual elapsed/RSS observations, median only as a descriptive baseline, and the order/timestamps. A synthetic idle-process measurement checks the supervisor itself but is neither a checker baseline nor a correction factor. No RSS peak subtraction is valid, and case elapsed differences from the baseline are descriptive only. All twelve baseline slots must have exact valid receipts. A baseline timeout, above-ceiling peak, nonzero exit, unexpected count, monitor/accounting/cleanup fault or missing custody is a launch pause and engineering diagnosis; it never stops a scientific family/observer size sequence or silently omits a baseline.

## Supervised measurement and uncertainty

Launch the existing target executable directly as the process-group leader using `Popen(start_new_session=True)`; no wrapper process or start gate. Use one owner for a single `os.wait4` reap, never `Popen.poll`, `wait` or `communicate` before it. Concurrent stdout/stderr draining retains complete raw bytes without blocking child exit. Record monotonic spawn, each ps call start/end, first/last sample, reap, pipe-drain completion and cleanup times. The elapsed checking observation is `reap - spawn`; drain and cleanup are separately recorded, never added to checker elapsed. At a target 10 ms cadence, obtain timestamped `/bin/ps` RSS samples for all members of the group and record per-process RSS and their sampled sum, actual collection latency/gaps and monitor errors. Coverage gaps include spawn→first sample and last sample→reap, not just intervals between samples. A zero-sample fast exit is valid only if the monitor ran without error and wait4/raw/cleanup custody is complete; report its full spawn→reap interval as uncovered. The sampled group sum can miss short peaks, can count shared pages more than once, and is not an atomic simultaneous group snapshot. It is an estimate, not a strict lower bound on true simultaneous group memory. `wait4` supplies the OS-reported child-accounting lifetime high-water RSS, including startup/exit intervals that sampling misses and potentially accounted-for descendants on macOS; the retained receipt field `child_peak_rss_bytes` names that value. It is not a simultaneous group peak or an exclusive target-process RSS value. Bind actual host unit conversion (macOS bytes, Linux KiB). The direct target identity, command, input hash, exit status, signals, stdout/stderr hashes/lengths, accounting result and group cleanup result are retained in a per-attempt receipt.

Freeze a per-process timeout, group sampled-memory ceiling, maximum sampled trace gap and cleanup deadline in the execution manifest after static host preflight. Polling is not instantaneous enforcement: the sampled ceiling may be exceeded between samples. A monitor kill after an observed above-ceiling group sample is `OBSERVED_MEMORY_LIMIT`; an above-ceiling wait4 child peak discovered only after normal exit is `OBSERVED_OVER_CEILING_AFTER_EXIT`, never described as enforced protection. A time threshold with valid attribution/cleanup is `OBSERVED_TIME_LIMIT`. These three **only**, after independent diagnosis confirms valid supervision and actual limit causation, trigger stopping larger sizes in that same profile/family. All other profile/family sequences continue and all 24 cells retain an explicit disposition; later cells in the stopped sequence receive `NOT_RUN_AFTER_LIMIT` with the exact triggering cell ID. An unattributed timeout, unavailable/invalid monitor sample, excessive trace gap on a sampled nonfast run, accounting failure, missing raw output, or process-group cleanup failure pauses all new launches for diagnosed tooling repair in this item. Preserve the failed attempt and original manifest, add a new exact tooling/execution binding, rerun the affected cell. A real-host positive sampled-RSS preflight and synthetic fast-exit, nonzero-exit, timeout, monitor-error and cleanup-failure negatives are required before any scientific launch.
