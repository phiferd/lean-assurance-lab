# Research priorities after the constitutional review

**What did we find?** The project has ten reusable November boundary inputs,
but only exploratory observations and container-specific runners for them. The
last audit found no source-supported bypass in its two inspected candidates;
it did not establish that useful local work was exhausted. Missing original
replay and recursor records still prevent verification of their reported results.
No scientific case ran in this reassessment.

**Is it interesting?** Yes. The constitution values usable shared tests and
clear visibility as well as finding defects. The current pause overlooked a
concrete consumer for existing inputs. Maintainer feedback on two prior Nanoda
PRs also shows that a technically useful test needs an understandable account
of the behavior it protects; neither PR has been merged.

**Does it require more work?** Yes. Select separate confirmation of the ten
known inputs for the Lab's checker-profile upgrade check, then gate their small
regression integration on that result. Keep an independently useful companion
to the public assurance snapshot READY. No historical experiment is repeated
and no upstream action is selected by this planning change.

## Constitutional assessment

The constitution needs no amendment. Its purpose is continuous, mechanically
reproducible visibility into Lean validation quality. It explicitly favors
shared assets, scoped claims, actionable recommendations and replaceable
methods, and rejects both a single-vulnerability hunt and metric optimization.

The recent NO_SIGNAL screens remain useful bounded observations. Their lack of
a defect-driven follow-up does not prohibit a separately justified consumer
integration. Conversely, packaging every completed experiment would create
maintenance work without evidence of use. Select one small consumer and prove
that it can use the result before expanding the corpus or creating more drafts.
This is a prioritization judgment, not a measured estimate of expected bugs or
community adoption.

## Delivery and evaluation

The updated frontier plan defines beneficiaries, decisive outputs, gates and
reconsideration triggers. The canonical queue and Active status select
`CONFIRM-CHECKED-IMPORT-CASES-1` READY, retain
`ASSURANCE-CLAIM-DISPOSITION-1` READY as a separate alternative, and leave
`CHECKED-IMPORT-REGRESSION-PACK-1` PLANNED behind successful confirmation.
The preceding completed audit and all frozen evidence retain their bytes.

Judge success by an independently runnable scoped package, useful detection of
changed or missing checking, and a comprehensible disposition of unresolved
claims. Record actual setup/replay effort and maintainer feedback. Do not use
case count, completed items, checker agreement, a mutation score, or new PR count
as the objective. Scale only when a named additional consumer or uncovered
mechanism justifies the maintenance cost.

One independent read-only strategic review compared reuse, receipt integration
and positive-suite compatibility; it supported the first option and stressed
preserving evidence-class and holdout boundaries. The owner of this change
made the final ranking. Aggregate delegate token use is unavailable; no cost
estimate is inferred. Validation evidence is retained in `validation.md`.
