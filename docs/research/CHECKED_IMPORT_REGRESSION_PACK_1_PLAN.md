# Integrate the confirmed checked import regression package

The proposed consumer is the Lab's manual checker-profile upgrade check. Its
value would be a single command that exposes a changed verdict or missing
checking operation on ten known inputs. Confirmation is still pending, so this
integration is PLANNED and unstarted; no fresh compatibility result is claimed.

Item: `CHECKED-IMPORT-REGRESSION-PACK-1`.
Evidence class: E2, bounded local regression integration.
Dependency: `CONFIRM-CHECKED-IMPORT-CASES-1` must close SUCCESS and its current
consumer/maintenance review must still support this package. No automatic
promotion from E0, E1, a green test or this plan.

## Fixed consumer contract

Reuse exactly the separately confirmed ten-case manifest and its two checking
adapters. Provide one documented repository command for the upgrade maintainer,
accepting explicitly identified supported executables/configurations and a fresh
output directory. First support the confirmed profiles; a version-change result
must bind both old and new identities and cannot inherit the old assurance claim.
Do not require an old task container name or an agent transcript.

The command inventories intended declarations, verifies input/runtime identity,
checks every requested case, and reports the observed result beside its scoped
expectation and reason. Missing cells and unsupported configurations fail closed
as incomplete, not as semantic rejections. Preserve raw stdout/stderr and actual
checker completion. Reuse the existing supervisor and checked-object tools;
do not create a general receipt service or another schema stack where the
existing manifest suffices. This is a manual small regression check, not a
scheduled whole-ecosystem campaign or a default expensive CI job.

## Integration gates and completion

Before integration, independently review the exact acceptance contract, bindings
and evidence-class boundary. Demonstrate the clean confirmed package and
controls for a missing case, changed input, substituted executable/no-op,
unattributable rejection and stale receipt. An injected checker-verdict change
must appear as a changed case, not an aggregate pass. These test integration
behavior; they do not establish sensitivity to every possible checker defect.

Deliver the command, unchanged input references, small manifest, focused tests,
one clean reproduction recipe, fresh integration evidence, and a short example
explaining a useful changed verdict. Require the applicable independent review,
replay, full closure and existing E2/milestone checks for this limited local
integration; never infer universal conformance or update the canonical assurance
gate from it. If a prerequisite fails, repair within scope or record the actual
boundary. Do not replace difficult cases or widen the corpus.

Only after successful local use and current source/duplicate/consumer review
should a separate Arena or checker contribution be proposed. No new upstream
draft backlog, reopening of closed PRs, or external write is authorized here.
At closure compare consumer value with the claim-disposition companion and any
new source-supported discovery opportunity, select one successor and stop.
