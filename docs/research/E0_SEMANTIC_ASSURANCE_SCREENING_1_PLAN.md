## Entry, scope and interpretation

Before any launch mark this one campaign ACTIVE in the queue and append each
trial's E0 start with its question, concrete inputs, profiles, commands, source
and tool identities, controls and signal criteria. Identify all shared/duplicated
terms and malformed/substituted targets before their respective observations.
Selection alone does not authorize a launch without those records. Trials 1/2
share one implementation; trials 3/4 add an independent implementation but
export/import contracts and versions remain possible confounders. Consensus
is not semantic authority. Trials 5/6 measure checking completeness and cannot
turn an intended-target failure into a kernel soundness claim.

Reuse existing binaries, fixtures, source, classifier, pipeline sentinel,
real-proof adapters and process supervisor. Run fresh supervised processes with
existing timeout, memory, positive observation and cleanup controls. No checker
source mutation, new importer, build-system project, library expansion or external
write is included. A shared-tooling requirement is a separately recorded
engineering proposal; do not turn this screen into another framework project.
Preserve every raw attempt and revision. Diagnose feasible ordinary engineering
faults within scope; process-control failures pause launches until reconciled.
Samples bound scientific scope, not permission to discard failures or cap repairs.

Recognized, controlled differences are candidate SIGNALs for diagnostic review.
NO_SIGNAL requires the declared question's observations and controls to be
complete. Missing demand, unsupported inputs, invalid controls or unavailable
observation is INCONCLUSIVE with its cause; report each trial independently.
Do not retrospectively promote any E0 observation into a scientific claim.
Compelling signals or useful shared-corpus opportunities get separate
confirmation proposals with fresh execution and their own gates.

## One campaign handoff

Record model responses deduplicated by response ID, cached and uncached input,
output including reasoning, coverage cutoff/missing records, process launches,
experiment and administrative retries, commits and actual delegates. Keep routine
counts deterministic. Use one short campaign summary: mechanisms exercised,
implementation agreement/differences/unobserved cases, reusable fixtures,
confirmation recommendation, and actual operational cost.

Use exploration-record and diff checks for each trial. Do not push transient
ACTIVE bookkeeping checkpoints solely to start trials. Aim for one or two
campaign commits; preserve failures even if delivery takes more. At handoff use
exploration-handoff --base <pre-campaign-commit> --write and --check; strategic
selection occurs once and leaves the successor unstarted. No per-trial assurance
refresh, receipt graph, full closure replay or independent closure review.
Memory accounting stays DEFERRED unless a named upcoming measurement decision
needs it. This campaign has no such dependency. Further workflow engineering
must identify a concrete obstruction; trial count is not the project objective.
