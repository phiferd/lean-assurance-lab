# Ecosystem closure and bounded autonomy

Authorized by the owner on 2026-09-05 after project review at `fd3e668`.
This is an explicit successor frontier; the completed publication study and
all its bound artifacts remain immutable. No external issue, comment, pull
request, email or disclosure may be submitted without target-specific human

## Objectives and stop conditions

1. Assemble a new input-bound decision packet for the four mature findings:
   imax, proof-parameter uniformity, possibly-Prop projection and reducible
   positivity. Check current upstream revisions and duplicates using read-only
   GitHub queries. Reuse exact prior reproductions when source/binary/case
   identities are unchanged; otherwise reproduce within the budget below.
   Preserve raw outputs and distinguish rejection, decline, crash, timeout and
   unknown status. Every action ends with a specific recommended target, draft,
   evidence, prerequisites and `REVIEW_REQUIRED`, or a justified no-action or
   concrete deferral. Do not regenerate historical preflight evidence.
2. Extend the existing campaign supervisor with a machine-readable authorized
   run manifest, exact input hashes, finite phase and total budgets, immutable
   attempt logs, interruption/resume and launch checks. Provide exact-hash local
   input materialization for a clean clone on the declared platform. Reuse the
   supervisor rather than creating a parallel scheduler. Retire or guard the
   old outer batch generator so it cannot reset an unattended run silently.
   Demonstrate one bounded real reproduction or evidence-validation case and
   fixture interruption/resume, changed-input refusal and budget exhaustion.
3. Select at most two of the nine existing pending survivors using only prior
   source/coverage evidence. Commit a fixed selection and finite protocol before
   candidate execution. Bound each survivor to at most 8 candidate attempts,
   16 checker launches and 120 active seconds; total at most 32 launches and
   240 seconds, with no new mutation generation or unbounded build. Reuse
   existing binaries only after identity validation. One isolated offline
   rebuild per selected mutant is allowed, at most 120 seconds each, using the
   already-installed Rust toolchain and existing dependency cache. Never modify
   the historical source checkout or observer binaries. Missing materialization or
   unsupported semantics ends as explicit bounded unresolved evidence, not
   equivalence. Every selected case receives a recommendation.
4. Assess whether a later prospective/held-out transfer study is justified only
   after the mature backlog is dispositioned. If human decisions remain pending,
   preserve this as a deferred proposal; do not start a speculative extra study.

## Execution bounds

Read-only upstream queries are bounded to four repositories, their relevant
branches and existing issue/PR inventories. Prefer one mechanically collected
inventory per repository over repeated search prompts. Cache exact responses,
query times and pagination closure. Failed retrieval is an explicit prerequisite.
No fresh large toolchain build or corpus campaign is authorized here. One
isolated offline build of the observed current Kiota commit is allowed, at
most 120 seconds, using the installed toolchain and dependency cache. Preserve
build failure as a concrete reproduction prerequisite; do not fetch new
toolchains or silently extend these bounds. Mature
finding reproduction is bounded to existing candidate/control pairs, at most
24 checker launches, 120 seconds each and 600 active seconds total. Run manifests
must be fixed before launch and charge attempted work; failures do not reset
budgets. New scientific ambiguity stops only dependent work and is flagged for
separate Ultra review when consequential.

## Mechanical acceptance

Focused tests cover manifest/frontier mismatch, input drift, missing payload,
no overwrite, stable resume identity, concurrent-run exclusion, process-group
termination, persisted budgets, and failure propagation. A clean clone must
materialize one exact declared input set and validate it without conversational
state. Run the required full-payload unit runner once after integration, the
historical study transition checks, action-record validation and current-state
refresh. Record raw negative results and current graph status. Update durable
research state and generated current reports using their generation paths.

## Cost discipline

Use scripts for hashes, input inventories, GitHub retrieval, execution, reporting
and validation. Luna handles narrow inventories; Terra handles bounded runner
implementation; the lead handles selection, scientific interpretation and
integration. Do not call models inside build/checker/minimization loops.
