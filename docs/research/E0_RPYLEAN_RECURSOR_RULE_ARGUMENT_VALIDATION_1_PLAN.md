## Fixed question and value

Does the exact current rpylean revision still admit Arena #350's dependent
recursor rule with the correct minor-premise head but a wrong constructor
argument, while accepting the unchanged honest rule, and is that case omitted
from the project's normal Arena test discovery because the harness scans only
top-level YAML files?

This is a current repair-readiness check, not a search for an unknown defect.
Its consumer is an rpylean maintainer deciding whether to derive the expected
minor application from the constructor telescope and compare all arguments,
and whether to make bug-fixture discovery recursive. The item is worth one
bounded screen because the source and public consequence already identify the
repair boundary; broader mutation, cross-checker transfer, historical credit,
or packaging would add cost without answering that decision.
