# Binder model pilot 1

Status: READY and unstarted, selected at the 2026-09-28 real-proof-slices
closure. Selection authorizes staged source and reuse preparation in a future
requested item. It does not establish the scientific or execution gates or
start model construction.

## Question and fixed scope

Do lifting and substitution, including compositions, agree with an
independently written capture-avoiding named-variable model on a finite,
explicit fragment? The pilot targets one fixed suite of 10,000 small valid
term/context operation vectors, covering nested lambdas, applications, lets
and open terms, through two supported implementation APIs. Preserve every
unsupported or invalid case disposition rather than replacing a selected
vector after an outcome.

## Staged preparation

First refresh focused primary-source and reuse evidence. Identify the exact
two supported API seams and a common tractable fragment before writing the
model or invoking an observer. Inspect existing formalizations, including
Lean4Lean, without assuming they supply an oracle for the selected operations.
Specify capture avoidance, alpha-equivalence, translation to de Bruijn terms,
validity/context rules and each lifting, substitution and composition check.
Bind an independent negative-capable translation and expectation auditor.

Freeze a deterministic 10,000-vector construction rule and exact source,
model, API, runtime, and observer identities before producing scientific
inputs. Commit the complete scientific and execution manifests, independently
review the protocol, run actual-host RSS preflight, and use supervised
nonterminal time, memory and cleanup controls before launches. Preserve raw
failed attempts and repair ordinary implementation or process defects within
the same item without changing frozen scientific inputs. Counts and elapsed
time are observations, never authorization or stopping limits.

## Closure

Deliver the executable independent model, audited portable vectors and exact
two-API comparison outcomes, or a characterized model/API/authority boundary
after feasible repairs. A distinguishing case needs local minimization and a
target-specific recommendation; agreement establishes only the bound fragment
and profiles, not full-kernel correctness. Run focused checks, the full
current/historical suite and dependency-ordered refresh, then reassess the
whole project. No external action is authorized by this plan.
